# Методология аналитического baseline

Этот документ описывает правила, которые реализованы в `src/apexflow`. Они
создают короткий и воспроизводимый список узлов для ручной AML-проверки. Роль
означает структурный паттерн в доступной выгрузке, а не установленный факт
нарушения.

## Границы данных

* Граф ориентированный: строка `src -> dst` означает наблюдаемый перевод.
  Узлы берутся из `nodes`, поэтому узлы без рёбер сохраняются в результате.
* Основой служат агрегированные `edges`; каждая пара `src,dst` должна быть
  уникальна. Повторные пары и ссылки на неизвестный `gid` считаются ошибкой
  входного контракта до аналитики.
* `gid/src/dst` сохраняются целыми int64 при сортировке и выдаче. Перевод через
  float запрещён: соседние идентификаторы порядка `10^17` могут слиться.
  `is_seed` — bool, `depth` — целое 0–4, `n_tx` — положительное целое.
  Веса — конечные неотрицательные числа; отрицательные суммы требуют отдельной
  модели возвратов и вызывают ошибку. Полная валидация файлов остаётся в пайплайне.
* `in_degree` и `out_degree` — число разных внешних контрагентов. Петля
  `gid -> gid` не добавляет внешнего контрагента. Суммы и `n_tx` считаются по
  наблюдаемым агрегированным рёбрам.
  `has_self_loop` и `self_sum` сохраняют наличие и сумму самопереводов. Узел с
  петлёй не считается изолированным. Для него отключены transit/terminal:
  одна петля не должна доказывать пропуск средств внешнему получателю.
  Сумма самопереводов указана в evidence и сохранена в агрегатах.
* `flow_ratio = out_sum / in_sum` только при положительном входящем обороте,
  иначе отсутствует (NaN только во внутренней таблице). Это не бухгалтерский баланс: входящие для seed могут быть
  неполны, а переводы меньше 5 000 KZT не представлены.
* `depth=4` — граница выгрузки. Ноль исходящих на этой глубине не доказывает,
  что узел конечный; поэтому `terminal` и `transit` там запрещены, а в
  `evidence` добавляется оговорка.
* Для seed transit/terminal также запрещены; evidence содержит оговорку о
  неполных входящих. Место для ограничений резервируется до сокращения основного
  текста до 200 символов, поэтому оговорки не теряются при обрезке.

## Признаки

Для каждого `gid` вычисляются `in_degree`, `out_degree`, `in_sum`, `out_sum`,
`in_n_tx`, `out_n_tx`, число уникальных соседей, `flow_ratio`, наблюдаемый
нетто-поток, достижимость из разных seed и посредническая центральность.
`observed_net = in_sum - out_sum`. Уникальные соседи — объединение внешних
плательщиков и получателей; встречная связь не удваивает их число. Изолят —
узел без любых рёбер, включая петли. Суммы считаются в float64; приведение
целых денежных столбцов выполняется до агрегирования во избежание переполнения
int64. Перед сложением строки сортируются по src/dst для стабильного порядка
операций. Исходные DataFrame при этом не меняются.
Счётчики `in_n_tx/out_n_tx` суммируются целыми Python без преобразования во
float: сохраняются единичные операции при значениях выше 2^53 и суммы выше int64.
Входной контракт сверяет целочисленные денежные столбцы edges и transactions
точно через целые Python, поэтому соседние суммы выше 2^53 не становятся равными
из-за округления float. Сами денежные аналитические признаки и CSV используют
float64; это не гарантирует бухгалтерскую точность на экстремальных оборотах.

Для денежных ролей отдельно вычисляются `external_in_sum/external_out_sum` —
суммы внешних переводов, и `funded_in_degree/funded_out_degree` — количество
внешних контрагентов с положительной суммой. Их пороги, role_score и evidence
используют именно эти значения: самоперевод и нулевая связь не доказывают
консолидацию/распределение денег. Внешние суммы агрегируются непосредственно по
рёбрам, а не вычитанием из общего оборота, которое теряет малые суммы рядом с
большой петлёй. Общие обороты и все внешние соседи сохраняются для priority_score.

Достижимость считается обходом ориентированного графа от каждого seed; простой
путь не перечисляется. Центральность — ненагруженная betweenness centrality:
точная при числе узлов не более 500, иначе воспроизводимая выборка из 128
источников с seed `42`. Денежные суммы не используются как длина пути.
Собственный seed не добавляется к достижимости, даже при обратном цикле.
В evidence указывается «достижим из N seed»: это число исходных seed-узлов,
а не доказательство независимых денежных направлений или общего управления.
Seed могут находиться последовательно на одном пути.
Выборочная центральность может быть нулевой даже у посредника; это ограничение
метода. Для точного воспроизведения версии библиотек должны совпадать.

Сообщества строятся на неориентированной проекции: веса противоположных
направлений суммируются, после чего применяется Louvain с seed `42`.
Перед Louvain веса делятся на максимальный положительный вес проекции. Это
предотвращает переполнение/исчезновение квадратов при общем масштабе очень
больших/малых весов. Отношения сохраняются в пределах точности float64:
если в одном графе одновременно есть веса 1e200 и 1e-200, малый вес может
обнулиться при нормализации. Такая разница масштабов не проверяется как
инвариантность кластеров. Суммы KZT в признаках и CSV не масштабируются.
Проекция включает только положительные веса без петель. Нулевые рёбра остаются
в направленном графе, количестве операций, соседях и достижимости, но не
объединяют денежные сообщества. Узел без положительных внешних связей получает
отдельный кластер; граф с нулевыми весами не вызывает деления на ноль.
Идентификаторы — **целые** `1, 2, 3, …` по общему контракту. Они
назначаются по минимальному `gid` в сообществе, поэтому не зависят от порядка
строк во входных файлах.
При изменении набора или версий постоянство номера не гарантируется.
`neighbor_cluster_count` — число других кластеров среди непосредственно
связанных внешних соседей в исходном графе, оба направления.
`sum_kzt_internal` включает каждое исходное направленное ребро внутри кластера
ровно один раз, в том числе петли. `top_gids` — JSON-массив до пяти целых gid по
убыванию приоритета, затем возрастанию gid. `n_seed` включает изолированные seed.

`hypothesis` описывает наблюдаемую структуру: сначала несколько seed, затем
наличие coordinator, consolidator, distributor, transit или terminal.
При наличии только terminal/peripheral текст сохраняет гипотезу конечного
получателя **в выборке** и предлагает проверить дальнейшие исходящие.
Одиночный кластер с наблюдаемыми связями отличается от изолята; одна петля
или нулевые внешние рёбра не называются связанной группой.

## Роли

Пороги привязаны к данным, а не к конкретным `gid`:

| Правило | Порог |
| --- | --- |
| «много входящих» | `max(3, Q75(funded_in_degree > 0))` |
| «много исходящих» | `max(5, Q75(funded_out_degree > 0))` |
| существенный входящий оборот | `max(1 KZT, Q75(external_in_sum > 0))` |
| высокая центральность | `Q90(betweenness > 0)` |

При пересечении правил выбран один результат в порядке: `coordinator`,
`distributor`, `consolidator`, `terminal`, `transit`, `peripheral`.

| Роль | Наблюдаемые условия |
| --- | --- |
| `coordinator` | высокая центральность, достижимость минимум из 2 seed и связи минимум с 2 другими кластерами |
| `distributor` | положительный внешний исходящий оборот и много получателей положительных сумм |
| `consolidator` | существенный внешний входящий оборот от многих плательщиков положительных сумм |
| `terminal` | не seed, нет самопереводов, глубина меньше 4, существенный входящий оборот и исходящий не больше 10% входящего |
| `transit` | не seed, нет самопереводов, глубина меньше 4, есть входящий и исходящий обороты, `0.8 <= flow_ratio <= 1.2` |
| `peripheral` | остальные узлы, включая изолированные |

`role_score` нормирует силу признаков роли через Q95 соответствующих метрик и
лежит в диапазоне 0–1. Он описывает силу правила в выгрузке; его нельзя читать
как вероятность нарушения.

Точные формулы: `S(x) = clip(x / t95(x), 0, 1)`, где t95 — Q95 положительных
значений, не меньше 1 для денег и счётчиков. Для центральности используется сам
положительный Q95 **без** нижней границы 1. Если положительных значений нет,
масштаб 1, вклад нулевой. Квантили используют линейную интерполяцию pandas.
Пустой набор положительных центральностей отключает coordinator.

| Роль | role_score |
| --- | --- |
| coordinator | `0.45*S(betweenness) + 0.30*S(n_seed_reachable) + 0.25*S(neighbor_cluster_count)` |
| distributor | `0.55*S(external_out_sum) + 0.45*S(funded_out_degree)` |
| consolidator | `0.55*S(external_in_sum) + 0.45*S(funded_in_degree)` |
| terminal | `0.55*S(external_in_sum) + 0.25*S(funded_in_degree) + 0.20*clip(1-flow_ratio/0.1, 0, 1)` |
| transit | `0.50*clip(1-abs(flow_ratio-1)/0.2, 0, 1) + 0.50*min(S(external_in_sum), S(external_out_sum))` |
| peripheral | `0` |

Все score ограничены [0,1]. Дополнительных caps 0.5/0.7 нет: ограничения
отражены в допуске к ролям и текстовых оговорках. Единица означает насыщение
эвристики, а не вероятность нарушения или доказанность гипотезы.

## Приоритет и проверка

Для глобальной очереди используется одинаковая для всех ролей формула:

`priority_score = 0.35*norm(log(1+in_sum+out_sum)) + 0.25*norm(unique_neighbor_count) + 0.25*norm(betweenness) + 0.15*norm(n_seed_reachable)`.

`norm` — min–max-нормализация по текущему запуску; если метрика одинакова у
всех, её вклад равен нулю. Сначала сортируется больший приоритет, затем меньший
`gid`, поэтому ранжирование стабильно. `top_nodes` содержит первые 20 узлов
или все узлы, если их меньше 20.
Логарифм вычисляется в эквивалентной устойчивой форме без предварительного
сложения двух потенциально очень больших оборотов. `why` выбирает до трёх
наибольших положительных **взвешенных вкладов** и показывает реальные показатели.
Положительная центральность выводится с тремя значащими цифрами, не округляясь
до 0.000. При нулевом score текст объясняет результат нормализации и порядок
по gid при равенстве score. Это не означает отсутствия структурных признаков:
например, все узлы симметричного денежного цикла могут иметь роль transit,
но одинаковые метрики дадут всем нулевой относительный приоритет.

Рекомендации для аналитика: по `consolidator` проверить источники поступлений;
по `distributor` — цепочку получателей; по `transit` — даты и суммы связанных
входящих/исходящих переводов; по `terminal` — дальнейшие внешние данные; по
`coordinator` — мосты между кластерами. Эти действия проверяют гипотезу и не
являются автоматическим заключением.

## Контракт и расширение

`analyze(nodes, edges, transactions)` не читает и не пишет файлы, не меняет
полученные DataFrame и не делает сетевых вызовов. Он возвращает только три
таблицы по контракту: `nodes_roles`, `clusters`, `top_nodes`. Аргумент
`transactions` сохранён в API для последующего временного анализа; baseline не
добавляет из него скрытых правил. Временные признаки должны быть добавлены как
отдельная, протестированная версия методологии, не меняя обязательные колонки.
Пустой граф возвращает три пустые таблицы с правильными схемами и числовыми
типами. Ошибки входа не заменяются пустыми результатами. Совпадение объёмов за
период не доказывает быстрый транзит или передачу конкретной суммы.

## Наблюдение, допустимый вывод и следующий шаг

| Наблюдение/ограничение | Допустимый вывод | Следующий шаг аналитика |
| --- | --- | --- |
| Несколько источников и большой вход | Признаки консолидации | Проверить источники и даты доступных операций |
| Много получателей и исходящий объём | Признаки распределения | Проверить ветви получателей и повторяемость переводов |
| Вход близок к выходу за период | Кандидат транзита | Сопоставить даты; совпадение сумм не доказывает передачу одних денег |
| Малый отток при существенном входе, depth<4 | Кандидат конечного получателя в выборке | Проверить полный период и внешние исходящие |
| Центральность, несколько seed и кластеров | Структурный посредник | Проверить конкретные мосты между сообществами |
| Нет исходящих на depth=4 | Ограниченная видимость | Запросить дальнейшие исходящие; не утверждать оседание денег |
| Seed с выходом больше входа | Неполный наблюдаемый баланс | Проверить недоступные входящие; не считать разницу задолженностью |
| Изолят | Недостаточно наблюдений | Проверить полноту выгрузки; не делать вывод о безопасности |

## Ограничения масштаба

Память pandas/NetworkX растёт с узлами и рёбрами. Обходы от seed стоят порядка
`S*(V+E)`, выборочная центральность — порядка `128*(V+E)`; Louvain зависит от
структуры графа. Измерение на 2 248 узлах нельзя переносить на миллион узлов.
Для этого потребуются компактное хранение, специализированные графовые
алгоритмы, контроль памяти, бенчмарки и ограничение видимых подграфов в UI.
Временные признаки — ближайшее отдельное улучшение после интеграции baseline;
разметки для обучения и оценки accuracy в предоставленном наборе нет.
