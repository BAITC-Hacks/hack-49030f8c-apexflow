## Команды для README (передать разработчику 3)

Достаточно Docker Desktop/Compose и Git, Python на хосте не требуется. Сначала
положить согласованные Parquet в `data/`, создать `output/`. На обычном Linux
задать APEXFLOW_UID/GID владельца output (`id -u` / `id -g`); не использовать
chmod 777. По умолчанию контейнер запускается с UID/GID 10001.

Чтобы manifest содержал commit, перед сборкой в PowerShell:

```powershell
$env:APEXFLOW_REVISION = git rev-parse HEAD
# Если есть незакоммиченные изменения кода, добавить суффикс -dirty.
docker compose down
docker compose up --build --force-recreate
```

Для Bash: `export APEXFLOW_REVISION="$(git rev-parse HEAD)"`. Без переменной
revision честно равен `unknown`; хэш файлов кода рассчитывается всегда.
URL: http://localhost:8501. Переменные APEXFLOW_DATA_DIR, APEXFLOW_OUTPUT_DIR и
APEXFLOW_PORT позволяют выбрать другие локальные папки и порт. Они используются
для изолированных тестов, не для передачи данных в облако.

```bash
docker compose --profile test run --rm --build tests
docker compose down
docker compose run --rm --build pipeline python -m apexflow --acceptance --json
docker compose run --rm --no-deps pipeline python -m apexflow --verify-output
docker compose up -d --force-recreate ui
docker compose run --rm --no-deps ui python tests/check_smoke.py
docker compose logs pipeline ui
```

`--json` выдаёт машинный отчёт. Любая ошибка расчёта или проверки даёт ненулевой
код; приёмочный режим не допускает синтетический набор вместо полного. UI
запускается через `depends_on: service_completed_successfully`; pipeline и tests
имеют `network_mode: none`. UI публикует порт только на 127.0.0.1. Ему оставлена
обычная bridge-сеть: internal-сеть в проверенном Docker Desktop не публиковала
localhost-порт. Отсутствие исходящих сетевых зависимостей UI проверяется отдельно,
это не сетевой firewall.

## Автоматическая интеграционная проверка

```bash
bash tests/compose_smoke.sh
```

Поддержан Bash на Linux и Git Bash с Docker Desktop на Windows. Скрипт создаёт
собственный синтетический набор в `.ci/smoke.*`, использует отдельный Compose
project `apexflow-smoke` и порт 18501. Не читает реальные `data/`, не перезаписывает
реальный `output/`. Проверяет сборку, pytest, настоящую аналитику, HTTP health UI,
чтение всех результатов, повторяемость хэшей CSV, сохранение после down, ошибку
при отсутствии Parquet и запрет старта нового UI после неудачного pipeline.
В конце останавливает только свой Compose project; отчёты остаются в `.ci/`.

CI запускает этот же сценарий для PR в staging/main и push в staging/dev/**, отдельно
проверяет статичный синтетический сайт в Node-контейнере. Отчёты pytest и логи
синтетического сценария сохраняются 7 дней. Никакие настоящие Parquet, результаты
или секреты workflow не загружает. Обязательные имена jobs для настройки защиты:
`static-demo`, `container-integration`, `release-policy`.

`release-policy` отклоняет PR в main не из staging. Это не заменяет настройку
защиты веток и не блокирует прямые pushes на уровне GitHub. Полный набор проверяется
локально командой `--acceptance`: защищённый канал доставки банковских данных в
GitHub Actions командой не согласован. Синтетический CI не является приёмкой
полного набора и не должен так описываться при релизе.

## Ограничения публикации и восстановление

Три CSV сначала записываются во временные файлы и перечитываются с проверкой всех
значений, затем заменяются. При обрабатываемом OSError уже заменённые CSV
восстанавливаются из временной копии. **Групповой атомарности при отключении питания
нет.** UI обязательно остановить перед пересчётом, как требует текущий договор.
При сбое run_status будет failed/running; verify-output отклонит такой набор.
Последний успешный manifest сохраняется для диагностики, но не объявляется свежим.

Если после аварийного завершения остался `.pipeline.lock`, сначала убедиться,
что pipeline-контейнер и любые другие процессы записи в этот output остановлены.
Только затем вручную убрать именно этот lock и повторить расчёт. Автоматический
сброс lock небезопасен: он мог бы разрешить два одновременных писателя.

Для переключения между неизменяемыми каталогами запусков потребуется изменение
договора с UI и работа разработчика 3. В этой ветке пути CSV не изменены. Сам UI
пока не читает manifest: не использовать старые CSV после ошибки через ручной
`--no-deps` запуск. Для ручного запуска сначала выполнить `--verify-output`.
