# Приёмка интегрированного ApexFlow

Дата: 23 сентября 2026. Этот документ фиксирует выполненные проверки и внешние
ограничения; исходные планы в `docs/team/` сами по себе не означают приёмку.
Точные версии кода, входные хэши и длительность каждого свежего расчёта находятся
в локальном `output/run_manifest.json`. Реальные CSV и Parquet в Git не входят.

## Окружение

- Хост: Apple M2, 8 CPU, 16 GiB RAM, Docker Desktop 29.8.0.
- Docker VM: aarch64, 8 CPU, 8 319 770 624 байт RAM.
- Runtime: Python 3.12, pandas 2.2.3, NetworkX 3.4.2, PyArrow 18.1.0,
  Streamlit 1.41.1; точная версия Python записывается в manifest.
- Прямые зависимости закреплены в `requirements*.txt`; первоначальная сборка
  требует доступа к реестру образов и пакетам. Анализ после сборки выполняется
  с `network_mode: none`.

## Воспроизводимые проверки

```bash
export APEXFLOW_REVISION=$(git rev-parse HEAD)
docker compose --profile test run --rm --build tests
docker compose build pipeline ui
docker compose run --rm pipeline python -m scripts.verify_dataset
docker compose up --force-recreate --wait --wait-timeout 120 ui
docker compose exec -T ui python -m scripts.ci_smoke verify /app/data /app/output
docker compose exec -T ui python -m ui.demo_examples
```

`scripts.verify_dataset` повторяет полный расчёт, проверяет байты трёх CSV,
равенство после перестановки строк, все gid в загрузчике UI, изоляты, ограничения
seed/depth=4 и неизменность исходников. Он печатает агрегированный JSON-отчёт.
Это локальный прогон реальных данных, а не замена браузерной проверки.

## Предыдущая интеграционная проверка

Интегрированная версия `9e6e21c` прошла 141 Python-тест за 5,27 с в test-образе
без сети и 6 тестов статического демо в `node:22-alpine` без сети. `node --check`
и `git diff --check` также завершились успешно. В pytest был один
DeprecationWarning NumPy о сложении даты в тестовой фикстуре; падений и skip нет.

На реальных данных `scripts.verify_dataset` подтвердил:

| Проверка | Фактический результат |
|---|---|
| Полнота | 2 248 узлов, 3 119 рёбер, 4 840 транзакций; все gid доступны поиску |
| Изоляты | Все 19 сохранены; каждый рисуется единственным узлом |
| Выходы | 2 248 строк ролей, 88 кластеров, топ-20 |
| Полный pipeline | 0,564239834 и 0,562163584 с, измерено вокруг всего вызова, включая manifest |
| Повторный расчёт | Побайтово одинаковые три CSV |
| Перестановка строк | Точные таблицы ролей, кластеров и топа совпали |
| Сохранность | SHA256 входов не изменились; analyze не изменил переданные DataFrame |
| Выгрузки | Все три буфера загрузчика UI побайтово совпали с файлами |
| Ограничения | Seed/depth=4 не назначены terminal/transit |

Это два запуска в уже собранном контейнере с установленными зависимостями;
время скачивания, сборки и старта контейнера в измерения не включено. Хэши
CSV совпали с [профилем данных](data_profile.md). Python runtime — 3.12.14.
Сборка выполнена из основной рабочей папки пользователя, где находились старые
CSV в корне: внутри готового образа проверено отсутствие любых Parquet и CSV.
Корневые экспорты исключены через `.dockerignore` и `.gitignore`.

Штатный Compose выполнил pipeline и перевёл UI в `healthy`. В дополнительной
проверке сеть UI была `internal: true`: runtime smoke подтвердил HTTP 200 внутри
контейнера, завершённый manifest и все 2 248 gid. Docker Desktop не предоставил
доступ с хоста к этой внутренней сети, поэтому браузерная проверка ниже проведена
в штатной сети Compose. Рендерер и Streamlit AppTest отдельно прошли без сети.
Отключение сети всего компьютера в браузерном сеансе не выполнялось.

В браузере на реальных результатах проверены поиск полного int64, карточка
приоритетного non-seed, предупреждение и следующий шаг depth=4, изолированный
seed, синхронизация выбранного кластера, поиск при пустом топе с фильтром роли,
ошибка нечислового gid и три события скачивания CSV. Период отображается
01.07.2026–31.07.2026. Направление и сумма наиболее крупного исходящего ребра
сверены с таблицей переводов. Синтетический режим при ошибках автоматически
не включается.

После визуальной проверки плотного графа устранены перекрытия длинных gid:
выбранный клиент находится в центре окружения, метки `№` обозначают локальные
номера, полный gid доступен в подсказке. Размеры узлов учитывают плотность и
обводки seed. Соседи со скрытым ребром не показываются как ложные изоляты;
настоящие изоляты и состав кластеров сохраняются. Две регрессии входят в 141 тест.

Ошибочный вход и неуспешный пересчёт проверены регрессиями; отдельный Compose
прогон с отсутствующими Parquet вернул exit 1, UI не был запущен. После остановки
и повторного создания контейнеров исходники и CSV остались на хосте.

## CI и выпуск

`container-ci` выполняет четыре проверки: `release-source`, `static-demo`,
`compose-and-tests`, `runtime-smoke`. Последняя генерирует явно синтетические
Parquet внутри образа, запускает настоящий CLI и зависимый UI, проверяет хэши,
поиск всех клиентов и HTTP readiness. CI не загружает реальные банковские
Parquet; полный реальный прогон проводится отдельно в разрешённом окружении.

PR в `main` допускается только из `staging` этого репозитория. Этот CI-контроль
не заменяет техническую защиту веток. 23 сентября GitHub API показал
`protected: false` у `main` и `staging`; страница Settings текущего аккаунта
показала `You don't have access to repository options`. Настройки защиты не
изменены. Администратору нужно включить PR, одобрение другого участника,
актуальные обязательные проверки выше и запрет force push для обеих веток.

Дополнительный внешний блокер повторён на новом PR #8: [run 35855191495](https://github.com/BAITC-Hacks/hack-49030f8c-apexflow/actions/runs/35855191495)
завершился с отказом всех четырёх заданий до старта шагов. В аннотациях GitHub: `The job was not started because
your account is locked due to a billing issue.` Устранение биллинга требует
владельца аккаунта/организации. Локальные Docker-проверки не выдаются за зелёный
Actions. Выпуск через `staging → main` должен дождаться настоящих обязательных
проверок; отключать их или подставлять успешные статусы нельзя.

## Действия с участием команды

- Другой участник должен самостоятельно повторить README: проверки агентом
  не являются подтверждением запуска другим человеком.
- Пятиминутная командная репетиция и личное участие на площадке требуют команды.
  Подготовленный сценарий — [demo.md](demo.md).
- Сдача на платформе проверяется отдельно по фактическому подтверждению.
  Коммит, PR, зелёный CI и локальные CSV не означают, что решение уже отправлено.
