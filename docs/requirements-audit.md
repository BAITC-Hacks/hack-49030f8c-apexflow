## Обязательные функции из ТЗ

| Требование | Где реализовано | Подтверждение |
|---|---|---|
| Одна команда, полный pipeline ≤5 минут, три CSV | `compose.yaml`, `src/apexflow/pipeline.py`, `io.py`, CLI | Compose, контейнерные тесты и реальный `scripts.verify_dataset`; время сборки отдельно |
| Роль, score, cluster и evidence для каждого узла | `features.py`, `rules.py`, `analytics.py` | Полнота 2 248 gid, все 19 изолятов, корректные схемы/диапазоны; evidence ≤200 символов |
| Формальные правила и пороги | README, `docs/methodology.md`, `rules.py` | Шесть правил, порядок применения, квантили и формула приоритета доступны для объяснения любого gid |
| Кластер каждого узла и сводка | `features.py`, `analytics.py`, `validate_outputs` | 88 кластеров, n_nodes/n_seed/внутренние суммы, JSON top_gids и гипотезы проверены |
| Топ ≥20, направления потоков, роли/кластеры, поиск | `app.py`, `ui/data.py`, `ui/graph.py` | Топ-20, поиск всех gid, AppTest и браузерная проверка стрелок, boundary и изолята |
| Не считать depth=4 конечным получателем; учитывать seed | `rules.py`, `app.py`, `site/app.js` | Seed/depth=4 не получают terminal/transit; пояснения соответствуют неполноте графа за тот же период |
| Локальный запуск без обязательных API/GPU | Dockerfile, Compose, зависимости и runtime-модули | Pipeline и тесты без сети; SVG без CDN; внешних AI-вызовов нет |
| Сохранять источники и не выдумывать атрибуты/роли | I/O, manifest, аналитические правила | Входы read-only, SHA256, правила по метрикам; персональные атрибуты не добавляются |

Требование объяснить три случайных gid за минуту поддерживается поиском,
evidence и документацией. Время устного ответа участника не измерялось:
подтвердить его должна командная репетиция.

с несколькими seed из примечания организаторов на странице 8 не задают

## Критерии оценки и необязательные функции

На странице 9 ТЗ приведены пять критериев на 100 баллов: работоспособность —
25, техническая реализация — 25, README/воспроизводимость — 25,
ценность/применимость — 15, потенциал/оригинальность — 10. В README добавлена
[матрица критериев](../README.md#критерии-жюри--максимум-100-баллов): для каждого
указаны реализованные доказательства и пределы подтверждения. Баллы проекта
не рассчитаны и не приравнены к максимальным весам.

Также явно описан статус всех восьми возможностей §8 ТЗ. Карточка узла есть;
граница глубины и полнота учитываются с оговорками. Временные паттерны,
специализированные детекторы маршрутов/аномалий, изъятие top-N и AI-ассистент
не выданы за реализованные функции. По ТЗ эти дополнения не блокируют сдачу.

README теперь содержит подтверждённые числа тестов, размеры выходов и время с
указанием среды, команды получения staging и различие Git Bash/PowerShell.
Текущая рабочая копия и интегрированная staging сравнены с проверенным кодом;
его отсутствие изменений позволяет использовать прежние тестовые доказательства.
На этапе PR #16 для правок текста использовались прежние доказательства.
По новому запросу проверки действительно повторены: 171 Python-тест,
6 Node-тестов, полный Compose smoke и два реальных расчёта.
Выявлена и исправлена одна неточность README: числовой Q90 центральности был
скопирован из раннего окружения NetworkX 3.5. Текущий NetworkX 3.4.2 даёт
0,0003882786150959452; исторические значения в методологии явно отделены.
SHA256 всех 13 сохранённых PDF/Parquet/CSV повторно сверены и совпали.

Статус внешних проверок описан в приёмке. По просьбе пользователя billing
исключён из текущей оценки функциональности проекта; локальные проверки
не превращаются от этого в успешный удалённый CI. При предыдущей проверке
GitHub API сообщал `has_pages: false`; публичный адрес не подтверждён.

## Исправления итогового аудита

1. Добавлены отсутствовавшие обязательные части README: технологии, встроенная архитектура, правила/пороги, масштабирование и повторяемая проверка жюри. Явно указан статус публичного deployment.
2. Настройка UID/GID Linux перенесена до запуска: исходный порядок мог дать `PermissionError` на обычном каталоге output владельца UID 1000.
3. Исправлены пояснение seed и следующий шаг: неполные входящие извне графа относятся и к наблюдаемому периоду, а не только к более ранним операциям.
4. Целочисленные суммы при сверке edges/transactions сравниваются точно. Расхождение на 1 около `2**53` раньше могло скрыться после преобразования в float; добавлены регрессии. Выданный набор этой ошибкой не затронут.
5. Удалено устаревшее сообщение статического сайта о необходимости интегрировать аналитику. Исторические планы и протоколы явно отделены от текущей приёмки. `.DS_Store` исключён из Git и образа.

## Доказательства и оставшиеся действия

Свежий итог контейнерных проверок фиксируется в [протоколе приёмки](acceptance.md).
Результаты первоначальной интеграционной проверки `9e6e21c` в старых документах
сохранены как история, а не переименованы в проверки нового commit.

Во время аудита разработчик 1 объединил `dev/pipeline-integration` в staging
через PR #13: расширенные provenance/CLI, lock-файл, откат публикации и Compose
smoke. Затем свежая staging включена в итоговую ветку с сохранением исправления
точности сумм. Из внешнего PR #14 также сохранены пояснение отсутствующих данных
и его UI-проверка. После объединения успешно повторены собственная сборка по
lock, полный smoke (171 тест) и реальный прогон; результаты указаны в приёмке.

Программный сценарий и обязательные материалы готовы к локальной демонстрации.
Полная организационная готовность не подтверждена:

- GitHub Actions завершает задания до запуска из-за billing-ограничения аккаунта; нужны действия владельца и успешный повтор CI. Локальные тесты его не заменяют.
- Настройки защиты веток требуют администратора. Наличие кода в main после внешних merge не доказывает соблюдение release-процесса.
- Другой участник должен самостоятельно повторить README. Команда должна провести пятиминутную репетицию и подтвердить личное участие по правилам.
- Схема решения есть в README/`docs/architecture.md`, CSV доступны локально в output; перед сдачей команда должна предоставить их жюри разрешённым способом и получить подтверждение отправки формы. `docs/submission.md` — подготовленный текст, а не квитанция о сдаче.
