# ApexFlow

ApexFlow — локальное рабочее место AML-аналитика для исследования структуры транзакционной сети. Оно помогает ответить на вопрос «какого клиента проверить следующим и почему?»: показывает приоритетную очередь, карточку клиента, его наблюдаемые связи, ограничения выборки и три выгрузки результата.

Результат не устанавливает виновность и не является вероятностью преступления. Роль и score — объяснимые гипотезы и порядок углублённой проверки; решение принимает специалист.

## Что реализовано в интерфейсе

- Поиск любого полного `gid`, в том числе большого int64, узла вне топа и изолята.
- Таблица глобального топа с фильтрами по роли и кластеру; поиск всегда проверяет полный набор, а не фильтр.
- Направленный граф выбранного окружения или кластера: стрелки строго `src → dst`, переключение окраски по ролям/кластерам, выделение выбранного узла и seed.
- Карточка с ролью, evidence, двумя score, глубиной, seed, наблюдаемыми входящими/исходящими суммами, ограничениями и безопасным следующим шагом.
- Таблицы наблюдаемых переводов, кластеры и скачивание трёх полных CSV без подмены их фильтрованной выборкой.
- Явно обозначенный синтетический режим для разработки. Он включается только вручную и никогда не подменяет отсутствующие реальные результаты.

Аналитические роли, кластеры и scores рассчитываются pipeline; интерфейс их не пересчитывает. Полный контракт данных — в [docs/team/00-contracts.md](docs/team/00-contracts.md).

## Входы и результаты

В Docker-контейнере UI ожидает только следующие смонтированные пути:

```text
/app/data/nodes.parquet
/app/data/edges.parquet
/app/output/nodes_roles.csv
/app/output/clusters.csv
/app/output/top_nodes.csv
```

`nodes_roles.csv` должен покрывать ровно множество `gid` из `nodes.parquet`; все `cluster_id` должны существовать в `clusters.csv`; `top_nodes.csv` должен согласовываться с результатами. При ошибке или отсутствии файлов UI показывает понятное состояние и не открывает искусственный пример сам.

## Основной запуск

Основной сценарий проекта — Docker Compose: Python и библиотеки на хосте для него не требуются.

```bash
docker compose up --build --force-recreate
```

Ожидаемый порядок: pipeline успешно создаёт три файла в `output/`, после чего UI открывается по адресу [http://localhost:8501](http://localhost:8501). Для остановки:

```bash
docker compose down
```

На этой ветке ещё нет `Dockerfile`, `compose.yaml`, pipeline и проверенных версий зависимостей: их создаёт разработчик 1. Поэтому команды выше являются согласованным целевым сценарием, а не заявлением о пройденной проверке. После их появления необходимо выполнить контейнерный прогон и заменить этот абзац фактическим результатом.

Для разработки самого интерфейса нужен только согласованный runtime с `pandas` и `streamlit`; UI не требует PyVis, Graphviz или внешней сети — граф выводится самодостаточным SVG.

## Публичная демонстрация в GitHub Pages

Для показа проекта без серверного окружения добавлена статичная версия в [site/](site/). Она не запускает Python-код и pipeline: GitHub Pages может отдавать HTML/CSS/JavaScript, но не может работать как Streamlit-сервер. В демонстрацию намеренно встроен небольшой **синтетический** набор; исходные банковские Parquet и результаты реального расчёта на публичную страницу не попадают.

Workflow [deploy-pages.yml](.github/workflows/deploy-pages.yml) публикует только `site/` при попадании изменений в `main` либо при ручном запуске. Перед первым развёртыванием владелец репозитория должен в **Settings → Pages** выбрать источник **GitHub Actions**. После успешного запуска Actions страница будет доступна по ожидаемому адресу [https://baitc-hacks.github.io/hack-49030f8c-apexflow/](https://baitc-hacks.github.io/hack-49030f8c-apexflow/).

## Проверка сценария

После появления реальных результатов проверьте:

1. Откройте интерфейс и убедитесь, что размер сети и кластеров взят из файлов, а не зашит в код.
2. Найдите обычный `gid`, gid за пределами видимого топа, изолят и узел `depth=4`.
3. При активном фильтре найдите gid с другой ролью: карточка должна открыться с сообщением, что поиск выполнился по полному набору.
4. Выберите известное ребро `A → B`: направление стрелки и `sum_kzt` должны совпасть с `edges.parquet`.
5. Проверьте, что роль, evidence и scores карточки совпадают с `nodes_roles.csv`, а скачивание возвращает все три полных CSV.
6. Повторите запуск после пересчёта pipeline и нажмите «Обновить данные с диска»; UI обязан прочитать новую версию файлов.

Проверки в Docker и без внешней сети выполняются после добавления Compose-разработки. Нельзя считать эту часть завершённой по локальному запуску Python.

## Ограничения и дальнейшее развитие

Граница `depth=4` не доказывает конечное получение средств; для стартовых seed могут быть неполными предыдущие входящие операции. Без размеченного ground truth проект не заявляет accuracy, precision или экономический эффект. После проверенного обязательного сценария возможны временные признаки, проверка чувствительности правил, промышленный контур доступа и работа с большими графами — это направления развития, а не текущие возможности прототипа.
